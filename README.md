# Codeck

一个轻量级的服务器 Agent 桌面：既可在浏览器中管理 tmux 终端，也可用适合手机的对话界面远程操作 Codex、Claude Code 和 QoderCLI。

## 启动

```bash
npm install
npm start
```

`node-pty` 是原生模块；如果当前 Node.js 没有对应的预编译版本，需要服务器具备 C/C++ 编译工具和 Python（Debian/Ubuntu 可安装 `build-essential python3`）。

打开终端中显示的 HTTPS 地址，并输入同一处显示的访问令牌。默认监听 `0.0.0.0:4310`，适合不经过 nginx 的可信内网；公网通过 nginx 反向代理时，应显式设置 `HOST=127.0.0.1`，再由 nginx 在外网监听 `3392`。代理必须允许 `/ws` 和 `/agent` 的 WebSocket Upgrade。所有会话 API 和加密 WebSocket 连接都必须提供访问令牌。未设置 `CODECK_TOKEN` 时，每次启动会自动生成一个随机令牌。

首次启动会通过 `openssl` 在 `~/.codeck` 生成并保存自签名 TLS 证书（设置 `CODECK_DATA_DIR` 时使用该目录），兼容不支持 `-addext` 的旧版 OpenSSL。启动时会检查有效期、私钥匹配、自签名和 localhost / 127.0.0.1 SAN；缺失或无效时，在临时目录生成并验证后替换。自动重建后浏览器可能需要重新确认信任。通过环境变量指定的证书不会被自动替换。浏览器会提示自签名证书不受信任，需要手动确认。正式部署可使用受信任证书：

```bash
CODECK_TLS_CERT=/path/to/fullchain.pem CODECK_TLS_KEY=/path/to/privkey.pem npm start
```

如果不希望直接开放端口，可改为仅监听本机并通过 SSH 转发：

```bash
ssh -L 3392:127.0.0.1:4310 user@server
```

需要固定令牌、端口或监听地址时：

```bash
CODECK_TOKEN='replace-with-a-long-secret' PORT=4310 HOST=0.0.0.0 npm start
```

`CODECK_TOKEN` 可自定义，并支持特殊字符；在 shell 或环境文件中设置时请使用引号保护令牌。

公网反向代理部署可设置 `CODECK_WEB_AUTH=1`，启用网页持久登录。首次输入 owner 访问令牌后，服务器会签发仅限当前主机、有效期 30 天的安全 Cookie；静态页面和资源需要该 Cookie，API 与 WebSocket 仍独立校验访问令牌。该选项默认关闭，可信内网直接运行时无需启用。

连续 10 次鉴权失败会让同一来源地址暂停尝试 5 分钟；公网 Nginx 还可以单独对 `/api/web-login` 配置请求限流。单会话分享链接有效期 24 小时且严格只读：可以查看、滚动和复制终端，但不能输入、上传、下载或管理会话，也不会把原有 tmux 客户端踢下线。

已配置的 `CODECK_TOKEN` 不会自动轮换。需要轮换时手动修改环境文件并重启 Codeck；旧的网页登录 Cookie 和分享链接会随即失效。未配置固定令牌时，Codeck 仍会在每次进程启动时生成新的随机令牌。

终端模式下，`codex`、`claude` 或 `qodercli` 必须已安装在服务器的 `PATH` 中。缺少某个 CLI 不影响 tmux 和普通 shell 功能。

## 普通终端链接

普通终端中的 HTTP/HTTPS 地址可直接单击，在新标签页打开，无需 Ctrl；Markdown 中显示出来的 URL 也可点击，拖选仍用于复制。使用 xterm 官方 web-links 插件，不将 Markdown 标签转换成 OSC 8 超链接。

自动折行的 URL 会保留路径、查询参数和锚点。上翻 tmux 历史时，Codeck 按需读取当前视口附近的原始逻辑行，并与可见文字逐字匹配，让完整显示的跨行历史 URL 也可点击，不需要重新生成输出。查询有范围和超时限制，不扫描整份历史；滚动、重绘或切会话后旧结果失效。被 tmux 顶部提示遮住、超出可见区域或因 CLI 自己插入换行而截断的地址不保证能还原，请先滚动到完整显示的位置。

## 手机对话模式

打开 `/remote.html`，或从终端页顶部进入“对话模式”。这个页面不解析终端字符网格，而是通过三套官方结构化接口统一显示对话、流式回复、工具执行、停止操作和授权请求：

- Codex 使用服务器上的 `codex app-server`，需要已安装并登录 Codex CLI。
- Claude Code 使用 Claude Agent SDK，并沿用服务用户的 `~/.claude` 登录和配置；通过 cc-switch 配置的路由也会继续生效。
- QoderCLI 使用 Qoder Agent SDK 和服务用户现有的 `qodercli login` 状态。

远程 Agent 只接受 owner 令牌，不接受单个 tmux 会话的分享令牌。手机页面中的“本次会话允许”会放宽后续同类工具操作，确认前应检查命令、路径和参数。工作目录必须是服务器上的绝对路径。

手机页左栏统一列出当前仍存在于 tmux 的 Agent 会话，不按 Codex、Claude Code 或 QoderCLI 分栏；主标题显示 Coding CLI 自己的 session 名，副标题显示 tmux 名和即时的工作/完成状态。已经退出 tmux 的历史会话不会显示。打开会话后，输入区上方会显示“正在思考”“正在运行命令”“正在修改文件”或“正在回复”等活动，并在 owner 模式下实时显示 tmux pane 中当前可见的 Agent 动作块。该摘录会清除 ANSI 控制符并限制行数，单会话分享令牌不会获得 pane 内容。

打开已有 tmux Agent 会话后无需“接管”：原来的 Coding CLI 会继续运行，手机输入会经服务端重新校验 provider、thread ID 和 tmux session，再只发送到该 CLI 的精确 pane。桌面终端和手机因此可以直接参与同一个 Codex、Claude Code 或 QoderCLI 会话；停止按钮会向同一 pane 发送 Escape，不会结束 CLI 或 tmux 会话。CLI 刚启动、尚未暴露持久化 thread ID 时，左栏会话仍可点击并发送首条消息；检测到真实 ID 后，Remote 会自动切换到结构化历史。会话若已退出、切换到其他 Agent，或身份无法精确确认，发送会被拒绝并提示刷新。

普通模式与 Remote 共用带进程 epoch 和递增 sequence 的会话快照流；同一份 tmux 扫描会分发给所有已连接客户端，浏览器只在推送异常时低频轮询兜底。Remote 打开会话后还会订阅精确绑定到 provider、thread ID 和 tmux session 的结构化 transcript 流，因此 Agent 最终输出不需要下一条消息触发。每次发送都带稳定的 `commandId`：断线后在同一服务进程内重试不会重复写入 tmux；若服务已重启、无法确认上次是否送达，界面会保留草稿并要求先检查终端，而不会盲目重发。

Remote 的乐观回显先标注“等待 Agent 确认”；获得 CLI 接收证据后显示“Agent 已接收”，真实对话记录出现后替换回显。接收不等于执行完成，前台工作、后台运行、等待确认、失败和未知状态分别显示。发送到 Codex 后若无法确认文字已提交，页面会保留草稿并阻止同一次输入重复投递；请从右上角切换到终端模式，检查文字是否仍在 CLI 输入框，再决定是否按 Enter 提交，不要重新粘贴整条消息。

Codex、Claude 和 Qoder 的待确认输入使用同一套排序规则：放在发送时已展示的内容之后，并在刷新、重连和后续输出到达时保留该位置，不按用户/模型角色重新分组。真实会话记录出现后，由真实记录替换待确认回显。

三种 Agent 共用发送确认和草稿清理规则：响应丢失后，可由当前会话的真实接收或对话记录解除待确认状态，不会自动重发；只清理该次发送的附件，并保留之后编辑的新草稿。向上阅读时，新事件和后台刷新不强制跳到底部；“直达最新消息”后仍可回看已加载的历史，重连缺口通过历史分页补齐。

普通模式和 Remote 的 `?` 只简要询问 Agent 理解的目标、当前进展、剩余事项和阻塞，不要求逐项拆解。它不打断当前节奏、不要求继续工作、不启动自主模式，也不改变方向或预算；Codex 排队消息不会被补发 Escape 强制执行。明确发送会替换终端旧草稿；原生审批弹窗仍按原交互处理。

自主任务使用三态交互：默认点击 A 进入规划；规划时显示“确认目标”和“取消”；确认后只显示黄色 A，点击退出并自动请求进展总结。确认在规划执行结束后可用，绑定当前任务并防止重复启动；取消会停止规划，不发送执行请求。浏览器草稿和附件保持不变，原生权限审批仍单独处理。

普通模式的圈 A（`Ⓐ`）位于右上侧“分享”左边；Remote 保持输入框上方位置。规划在当前对话中完成，不打开配置弹窗，也不额外请求模型提取参数。确认时明确要求 Agent 尝试 get_goal / create_goal，复用一致的原生目标；遇到不同的未完成目标时先报告冲突，不覆盖。预算未指定就不添加默认值。原生 goal 不可用时，Agent 说明跨回合续跑限制后按 iterate 执行，Codeck 不另建续跑调度器。

A 发送沿用普通消息的身份核对和投递确认，保留浏览器中未发送的草稿；与 `?` 一样，不补发 Escape 强制打断当前执行。若 Agent 正在等待原生问题或审批，先引导用户处理，不把规划提示词注入选择菜单。发送期间防重复点击；切换会话、刷新或重连不自动发送。规划是否及时返回仍取决于当前 Agent 的执行与排队情况。

确认后 A 变黄，Agent 的开始回执补充具体目标。只有结束回执才能报告任务结果，普通回复结束和终端空闲不算完成。自然完成后保留完成态与总结，点击 A 只退出自主模式，退出后再次点击才开始规划。执行中点击 A 会先停止前台，并在 Codex 中通过受保护的原生命令清除可见 goal，再请求清理与交接总结。退出请求期间禁止重复点击，无法确认停止、投递或清理时显示原因并保留重试退出入口，不冒报成功。

结束回执必须包含 cleanup 资源清理核验记录。Codeck 等最终答复结束，再清除可见的原生 goal，确认会话身份及前后台执行状态，回收本轮回执目录和闲置轮询计时器，保留结果、证据与版本记录。手动退出、取消规划和独立停止按钮统一走清理流程：请求 Agent 清理任务创建的进程、子 Agent、临时文件和连接，等待带证据的清理回执，再核验运行状态，最后退出。规划取消保留进入规划前已有的 goal。清理失败、缺回执或仍有后台运行都保留失败与重试入口；旧版无 cleanup 的结束回执同样需要重试清理。资源归属由 Agent 根据任务记录核验，Codeck 不批量停止无法区分归属的进程，也不能独立证明任意外部资源已销毁。

规划提示词完整保留自主探索、假设与实验、证据驱动调整、严格验证、保留可靠成果、预算与停止条件、持续记录和最终交接原则，并要求检查项目指令与可用的相关 Skill。确认后不在每轮反复询问是否继续，进度问询不重置目标或预算；不要求 Agent 输出协议 JSON。

新规划发送前只分配本次任务专属的规划就绪、开始和结束回执位置，不读取历史、不调用额外模型。Agent 整理好计划并记录就绪后才允许按钮确认；终端短暂空闲不代表计划完成。Agent 通过本地命令写入回执，用户对话不要求输出协议 JSON；Codeck 不把普通回复结束当作目标完成，也不独立证明 Agent 提交的验证结论。旧任务的迟到回执不能覆盖新任务，服务重启不会发送规划、工作或总结。旧配置接口、独立模型提取、配置表单、逐轮调度及版本 1/2 存档已停用；状态仍使用版本 3，更新前未确认的规划可取消后重新规划。

Remote 的未知发送回执在重连时按原历史锚点恢复，不用相似文本冒充发送确认。无法核实的旧回执可点“清除此提示”，仅清理提示，不重发、不删除真实对话，也不清空草稿。清理记录保存在当前浏览器并传回服务端，刷新或重新连接后继续生效。

普通输入和进度问询不重置目标或预算；规划和执行期间隐藏 ? 快捷按钮，仍可直接发送消息。退出总结停止前台和原生 goal，不清理无关后台任务；其他任务停止仍使用独立的原生终端操作。普通模式重新连接时按当前窗口恢复尺寸，不沿用手机窄屏设置。

Qoder 多行粘贴会先验证空输入框，再等待本次正文或匹配的粘贴摘要出现，才发送 Enter；等待有界，未观察到内容时保留“发送未确认”，不重复粘贴。识别支持带会话标题的输入框、中英文占位符，以及思考强度/上下文窗口等底栏设置；明确发送或确认新目标时自动替换旧草稿；后台后续轮次不擅自清空新的人为输入。原生审批弹窗不会被当成草稿覆盖。自主发送、人工输入和浏览器滚动共享 session 队列，终端协议回复除外。

普通模式连接或滚动后，首个人工按键与输入框交权一样，按序退出 tmux copy-mode 并原样交给 CLI；后续按键也经共享队列传入，避免其他连接的滚动抢占。滚动和终端协议回复本身不退出 copy-mode；断线时禁用输入，重连后重新确认输入状态，不重放断线输入。

`/status`、`/usage`、`/model` 等命令的终端返回会进入命令弹窗。只有后端实际支持交互的模型菜单才显示可选按钮；不支持原生选项操作时保留可读输出，可切到普通终端处理，不把错误或缺失结果显示为操作成功。

发送 Codex 消息或斜杠命令前，Remote 会检查终端输入框是否为空。如果终端已有未提交草稿，或当前画面无法确认输入框已就绪，本次输入不会写入终端，Remote 草稿和附件也会保留。请先切换到终端处理已有草稿或选择弹窗，再返回 Remote 发送；不会自动把新消息追加到旧草稿，也不会自动清空旧草稿。

QoderCLI 按普通终端语义发送，不再要求从终端画面确认输入框为空；工作中、YOLO 模式、主题或状态栏变化不会因此阻止发送。会话身份和精确 pane 校验、防重复投递仍保留；发送后若无法确认提交，会提示检查终端，不会自动重发整条消息。注意：终端已有草稿时新文字可能追加进去，弹窗也可能接收按键，请先在普通终端处理这些状态。

Qoder 的 `Asking User` 单选弹窗按问题、连续编号选项、辅助入口和导航提示识别，兼容换行、大小写、末尾标点、分隔线及可选的 `Chat about this`。Remote 只展示实际答案；文字输入、继续讨论和多选仍在普通终端处理。缺少完整菜单、辅助入口未知或光标已进入编辑区时不操作；提交前重新核对当前问题和光标，避免误选或重复回答。

Qoder 普通单行文字和回车通过同一份原始终端输入发送，避免忙碌时粘贴与回车被合并成换行；多行输入保留括号粘贴。Codeck 也会核对 Qoder 自己的输入日志：确认收到后显示“Agent 已接收”，不会因为排队或 steering 尚未产生独立对话记录而超时变成未知。收到不等于执行完成；真实记录出现后才替换这条回显，确认延迟期间编辑的新草稿不会被清空。

Remote 输入框左侧的 `＋` 支持从相册、相机或文件选择器添加附件，也可以直接粘贴图片或在桌面拖入文件。每次最多添加 10 个附件，单个文件最大 10 GiB（10 × 1024³ 字节）；发送时文件会先上传到 `~/.codeck/uploads/remote`，再把服务器路径交给 Codex、Claude Code 或 QoderCLI 读取。Shell 会话不会单独执行附件路径，必须先输入要运行的命令，Codeck 再把安全引用的路径追加到命令末尾。

上传采用流式写盘，不把完整文件装进内存；断传、超限或校验失败会清理临时文件，不覆盖已有完整文件。大文件仍受磁盘空间限制，上传大小不代表 Agent 能直接处理同等大小的内容。HTTP 请求体总时限为 24 小时，上传连接空闲时限为 180 秒。

反向代理的 Codeck `server` 配置必须同步设置 `client_max_body_size 10g;`，并在代理 `location` 设置 `proxy_request_buffering off;`，避免 Nginx 默认 1 MiB 限制或将整份文件缓存在系统盘。保留 `proxy_http_version 1.1;` 和合适的 `proxy_read_timeout` / `proxy_send_timeout`，修改后执行 `nginx -t` 再平滑重载。

在支持浏览器语音识别的设备上，Remote 输入框右侧会显示麦克风按钮。点击后允许麦克风权限即可把普通话实时写入当前草稿，再次点击停止，确认文字后仍由发送按钮提交；不支持该接口的浏览器会自动隐藏按钮。Codeck 服务端不会接收或保存录音，但浏览器或操作系统可能把语音发送给其在线识别服务，因此语音输入通常需要联网，并应通过 HTTPS 使用。

普通终端模式也会在终端标题栏和手机快捷键栏显示语音入口。点击后会在终端下方展开与 Remote 一致的内联输入条，识别结果可先编辑确认；点击发送会把文字和 Enter 一并发给当前终端，关闭按钮可随时收起输入条。

连接终端后，可以从剪贴板直接粘贴 PNG、JPEG、WebP 或 GIF 图片。Codeck 会将图片保存到服务用户的 `~/.codeck/uploads`（单张最大 10 GiB），并把服务器文件路径输入当前会话，供支持图片路径的 Agent CLI 读取。

也支持将本地文件/文件夹直接拖拽到终端区域。拖拽目录会保留目录结构，上传后的文件路径会按同样路径写入 `~/.codeck/uploads` 并在终端中自动写入对应路径。

支持从终端中选中 `~/.codeck/uploads/...` 下的文件路径直接拖拽到本地下载。公网持久登录模式使用 HttpOnly 登录 Cookie 鉴权，不会把 owner token 写入下载 URL 或代理日志；直接调用下载 API 时也可以继续使用 Bearer token。
