# 条件任务

配置示例（用户已授权定期执行后使用，路径和会话名按实际填写）：

```json
{
  "session": "research",
  "everyMinutes": 30,
  "cwd": "/data/code/project",
  "check": ["/usr/bin/python3", "/data/code/project/check_new_data.py"],
  "prompt": "分析本次新增资料，保留来源和证据，更新现有报告。",
  "enabled": true
}
```

检查程序应为低成本、只读操作。直接执行 argv，不隐式启动 Shell；需要 Shell 时明确配置 `/bin/bash` 和脚本路径。运行服务用户与 Codeck 相同。检查程序退出 0 且 stdout 输出非空的稳定事件标识（如财报 ID 或文件摘要）才允许派发；无变化时返回非零或空输出。异常、30 秒超时、输出超过64KB均不派发。不要输出凭据，不要在标识中包含每次变化的当前时间。

后台每30秒检查到期配置；同一任务记录已投递事件，同一目标忙碌时延后。配置绑定当前 provider/thread，换会话后需重新配置。系统仅尝试提交一次，接收/执行结果仍以 Agent 回执为准；投递中崩溃或 ACK 丢失标为不确定并停止后续自动派发，先只读核实，再由用户决定删除重建。删除后重建会清空事件去重记录，不能用于盲目重试。长时间关机不补发所有错过的周期。

`codeck task put` 更新同 ID 时保留已派发事件；`enabled:false` 暂停检查。不要把用户未指定的预算转换为默认预算，任务提示词保留原目标、边界和停止规则。
