# 进度便签

便签是任务记录，不是运行状态或新的授权。`?` 汇报与确认推进在关键节点调用本 Skill 更新；不为填便签额外启动模型或恢复任务。不输出内部 JSON 给用户。

简短文本仍可用 `codeck session checkpoint NAME --file NOTE.txt`。结构化记录写入本地文件后：

```sh
codeck session checkpoint NAME --record NOTE.json
```

```json
{
  "text": "回归中，已复现输入失焦",
  "progress": {
    "goal": "恢复断线后的输入与翻页",
    "verified": "已复现，并验证了定位假设；尚未部署",
    "current": "运行浏览器回归",
    "next": "通过后部署并复核实际页面",
    "needsUser": "",
    "constraints": "保留真实会话和已有草稿",
    "evidence": [{"label": "验证页面", "url": "https://example.org/evidence", "version": "实际版本"}]
  }
}
```

只填有依据的字段；摘要建议不超过40字，内部JSON字段不显示给用户。证据可用本站 `/pages/ID` 或 HTTPS；不把任意本地路径伪装为可点击下载。没有可打开的证据可写在 verified 中，明确位置及验证范围。不要写凭据。

每次 `progress` 为当前任务完整记录，省略字段会移除该字段；只更新文本不会清空结构化进度。`needsUser` 仅用于会改变目标、权限或验收的真实待判断问题，附依据。用户已处理后更新为空；点击已读只消除通知，不冒充问题解决。

明确开始新任务时加 `"newTask": true`：旧记录归档，新任务不继承旧验证或错误。thread变化不会自动把旧成果当作新任务成果：界面标为历史归属，直到Agent明确写入当前任务。临时身份丢失仍保留旧记录，运行状态不受影响。写入需要当前明确的会话身份；遇身份变化先读取核对，不自动重发给其他session。

当前没有运行自动全文提炼、周期巡检或后台模型。便签来自 Agent 的显式更新，时间标识用于判断新旧。`--file`保留对旧文本工作流的支持。
